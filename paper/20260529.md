## 一、总体描述

**完整的 task-driven 光电混合 NoC 仿真**：电层控制面握手 → 光层数据直传 → 可重构波长分配 → 设备级光链路预算 → RC 热模型 → DVFS 节流 → 微环静态热调谐功耗 → SOA 逐跳放大与能耗追踪。

```
控制面（电）:  setup_req → 电 router → setup_ack
数据面（光）:  data flit → sendDirect → 光波导一跳直达
热调谐（常驻）: 160 微环/路由器 × 2mW/环 → 320mW/路由器 → 注入 RC 热模型
SOA（逐跳）:   每路由器输出端口后 SOA × 80mW/器件 → 按电路持续时间累计能耗
```

## 三、光路由器微环架构

### 3.1 路由器结构

5 端口 microring-based 光路由器，端口定义：**0=Local, 1=West, 2=North, 3=East, 4=South**。

物理实现为 waveguide crossing 交叉杆拓扑：5 条输入波导 × 5 条输出波导，有效交叉点 20 个（排除 5 个自路由对角 `inPort==outPort`）。

### 3.2 微环数量

每个交叉点串联 8 个微环谐振器（每 WDM 波长一个）：

> **20 有效交叉点 × 8 波长 = 160 微环/路由器**

4×4 Mesh 共 16 个路由器：**16 × 160 = 2560 个微环（全芯片）**。

### 3.3 各方向路径经过的微环数

代码位置：`src/onoc/common/OpticalDeviceModel.cc:70-128`，`buildWavelengthDependentRouterMatrix()`。

throughCount 公式（n=8 波长，i 为波长索引 1..8），每路径额外 **dropCount=1**：

| 方向组 | 公式类型 | through 范围(i=1..8) | 最长(i=8) |
|--------|:---:|:---|:---:|
| L→W, W→S, N→L, E→N | Type 0: i−1 | 0–7 | 8 |
| L→S, N→W, E→L, S→E | Type 1: 2n+i−1 | 16–23 | 24 |
| L→N, L→E, W→L, S→L | Type 2: 3n+i−1 | 24–31 | 32 |
| W→E, N→S, E→W, S→N | Type 3: 4n | 32（恒定） | 33 |
| W→N, E→S | Type 4: 4n+i−1 | 32–39 | 40 |
| **N→E, S→W** | **Type 5: 6n+i−1** | 48–55 | **56** |

> 物理含义：through 环 = 信号路径上处于 off-resonance 态的其他波长微环；drop 环 = 出口交叉点处目标波长的微环（耦合输出）。最长路径 N→E 经过 6 个中间交叉点（6×8=48 through）+ 出口交叉点（7 through + 1 drop）= 56 环。自洽验证：48 + (8−1) + 1 = 56 ✓

## 四、微环热调谐功耗

### 4.1 静态热调谐（2026-05-28 已实现）

每个微环需要恒定的加热功率将谐振波长对准 ITU 栅格目标。这是**常开功耗**，与光路建链/拆链无关。

实现文件：
- `src/onoc/control/LogicalTopologyManager.ned` — 新增参数声明
- `src/onoc/control/LogicalTopologyManager.h` — 新增成员变量
- `src/onoc/control/LogicalTopologyManager.cc` — 核心逻辑

实现方式：
```
initialize():
  routerTuningPower_mW = opticalNumRingsPerRouter × opticalRingTuningPower_mW_per_ring
  for each router: tm->addRouterOpticalPower(routerId, tuningPower_W)  // 永久注入，不 remove

finish():
  totalEnergy_J = numRouters × routerTuningPower_W × simTime()
  recordScalar("onoc-ring-tuning-*", ...)
```

### 4.2 初始化顺序 Bug 与修复（2026-05-28 发现）

**Bug**：`LogicalTopologyManager::initialize()` 在 `ThermalModel::open()` 之前调用 `addRouterOpticalPower()`。此时 `numRouters==0`（构造器默认值），`addRouterOpticalPower` 中的 `routerId >= numRouters` 检查（`0 >= 0` 为 true）静默返回，**ring tuning 功率从未注入热模型**。

NED 子模块初始化顺序为 `topologyManager → pe[]`，而 `ThermalModel::open()` 在 `pe[0].initialize()` 中调用，晚于 `topologyManager`。

**修复**：`ONoCMesh.ned` 中将 `pe[]` 移到 `topologyManager` 之前，确保 `open()` 先执行。

**修复前后对比（MPEG4）**：

| 指标 | 修复前 | 修复后 | 变化 |
|------|:---:|:---:|:---:|
| 完成时间 | 179.7 μs | 191.5 μs | +6.6% |
| 路由器平均温度 | ~47.7°C | ~50.1°C | +2.4°C |
| PE1 DVFS 因子 | 1.108 | 1.182 | +6.7% |
| PE1 启动温度 | 49.0°C | 50.5°C | +1.5°C |

> 修复前 `onoc-ring-tuning-total-energy-J` scalar 仍正确报告（参数×时间直接计算），但热模型实际未收到该功率。修复后 scalar 值不变，但温度同步上升。

## 五、SOA 放置位置与能耗追踪（2026-05-29 新增）

### 5.1 SOA 放置位置分析

**结论：SOA 必须放在光路由器内部（逐跳放大），不能只放在 PE 调制器之后。**

#### 关键问题

256 Gbps PAM4（128 GBaud）下，链路预算紧张：

| 环节 | 损耗/增益 | 说明 |
|------|:---:|------|
| 片外激光器发射功率 | 0 dBm | 1 mW |
| 光栅耦合损耗 | -3 dB | 光纤→片上光栅耦合器 |
| 1×16 分光器 | -12 dB | 10·log₁₀(16) |
| 分光器额外损耗 | -1 dB | excess loss |
| **每分支入纤功率** | **-16 dBm** | 仅 25 μW |
| 调制器 | -1.0 dB | λ₁ drop 环 |
| 每路由器 traversal | -2.5 ~ -4.8 dB | through 环 + drop 环 + bend |
| 路由器间波导 (0.15 cm) | -0.225 dB | 1.5 dB/cm |
| SOA 增益 | +13 dB | 小信号增益 |
| PD 灵敏度 | -18 dBm | 接收阈值 |

#### 场景 A：SOA 仅在 TX（调制器之后）

```
入纤功率 -16 dBm → TX SOA 13 dB → -3 dBm → 调制器 -1 dB
→ 路由器1 -3.4 dB → WG -0.2 dB → 路由器2 -3.4 dB → WG -0.2 dB
→ 路由器3 -3.4 dB → WG -0.2 dB → 路由器4 -3.4 dB
→ 解调 -1.0 dB → PD -0.5 dB
= -20.0 dBm  ← 低于 -18 dBm 灵敏度 ✗
```

**单 TX booster 无法支持 ≥4 跳路径。** 4×4 Mesh 中最长路径 6 跳（对角），完全不可行。

#### 场景 B：SOA 在每个路由器输出（当前方案）

```
入纤功率 -16 dBm → 调制器 -1 dB → 路由器1 -3.4 dB → WG -0.2 dB
→ SOA +13 dB = -7.7 dBm   ← 恢复
→ 路由器2 -3.4 dB → WG -0.2 dB → SOA +13 dB = +1.7 dBm  ← 恢复
→ 路由器3 -3.4 dB → WG -0.2 dB → SOA +13 dB = +11.0 dBm ← 恢复
→ 路由器4 -3.4 dB → WG -0.2 dB → SOA +13 dB = +20.3 dBm → 饱和裁切至 15 dBm
→ 解调 -1.0 dB → PD -0.5 dB = +13.5 dBm  >> -18 dBm ✓
```

**逐跳 SOA 可支持任意跳数路径，6 跳对角无压力。**

#### 对比总结

| 维度 | SOA 在调制器之后 | SOA 在路由器内部（逐跳） |
|------|:---:|:---:|
| 支持 3 跳以内 | ✓ | ✓ |
| 支持 4+ 跳 | ✗ | ✓ |
| SOA 总数 | 1/光路 | N/光路（N=跳数） |
| ASE 噪声 | 单次 | 级联（已建模） |
| 增益饱和风险 | 低 | 中（代码中已裁切至 Psat=15 dBm） |
| 256 Gbps 可行性 | **否** | **是** |

### 5.2 SOA 电能耗追踪

#### 实现原理

每条光路建立时记录时间戳，拆除时按电路持续时间累计电能：

```
energy_J = SOA数量(跳数) × opticalSoaPumpPower_mW × 1e-3 × 持续时间(s)
```

核心代码路径：
- `tryAllocateOpticalPathForPacket()` → `alloc.setupTime = simTime()`
- `releaseOpticalPathForPacket()` → `energy = soaCount × pumpPower × duration`
- `finish()` → 遍历残留电路补计 + 输出 scalar

#### SOA 能耗 Scalars

```bash
grep "onoc-soa" results/ONoC_MPEG4-#0.sca
```

| Scalar | MPEG4 实测值 | 说明 |
|------|:---:|------|
| `onoc-soa-pump-power-mW` | 80 | 每 SOA 电泵浦功率 |
| `onoc-soa-total-energy-J` | 6.89×10⁻⁷ | 全仿真 SOA 总电能 |
| `onoc-soa-total-circuit-hops` | 44 | 所有光路的 SOA·跳 累计 |
| `onoc-soa-average-power-W` | 3.60×10⁻³ | 时间平均功率 |
| `onoc-soa-energy-per-hop-J` | 1.57×10⁻⁸ | 每 SOA·跳 平均 15.7 nJ |

#### 边界情况处理

- **自然结束 (`endSimulation()`)**: `isAllDataSent()` 要求 500ns grace period + TEARDOWN 已同步完成 → 无残留电路
- **`--sim-time-limit` 截断**: 可能有电路在 FES 队列中未触發 TEARDOWN → `finish()` 遍历残留电路补计能耗
- **`duration ≤ 0`**: 跳过（同一 simTime 立即拆除的瞬时电路）

## 六、波长分配机制

### 6.1 分配触发时机

波长分配在 `LogicalTopologyManager::tryAllocateOpticalPathForPacket()` 中完成（`src/onoc/control/LogicalTopologyManager.cc`），由源路由器上的 **ReconfigurableOPCalc** 在第一个数据 flit 到达时触发。

### 6.2 完整流程

```
源 PE 完成计算 → 需要发数据给下游
        │
        ▼
① 电层握手 (setup handshake)
   - TaskPE.cc 调用 tryReserveSetupPath(dst)
   - LogicalTopologyManager 在 edgeOccupancy 中预留波长+空间通道
   - 通过电路由器发 SETUP_REQ（2-flit 控制包，taskId=-1）
   - 目的 PE 收到后发 SETUP_ACK 回应
   - 源 PE 收到 ACK，标记 circuitReadyByDst[srcIdx] = 1
   - 超时重试：setupRetryDelay=50ns, setupPendingTimeout=200ns
        │
        ▼
② 数据 flit 触发波长分配
   第一个 NOC_START_FLIT 到达源路由器时 (ReconfigurableOPCalc.cc):
   - 若 srcId == routerId 且波长尚未分配
   - → topologyManager->tryAllocateOpticalPathForPacket(src, dst, pktId)
        │
        ▼
③ 核心分配算法
   a. buildXYPathEdges() — XY 维序路由边列表
   b. 确定所需波长数（默认 2 个）
   c. 遍历空间通道: isWavelengthFreeOnPath() → 收集空闲波长
   d. 策略 "lowest": 取最小的 required 个空闲波长
   e. 占用: edgeOccupancy[spatial][wlIdx] = pktId
   f. 预计算设备级光链路预算并缓存
   g. 所有空间通道不足 → insufficientResources = true
        │
        ▼
④ 光层数据直传
   TaskPE::sendOpticalFlitFromQ()
   - 从 opticalDataQ 取 flit
   - sendDirect(flit, propDelay, txDuration, targetMod->opticalIn)
   - 数据 flit 端到端光路直传，完全绕过电路由器
        │
        ▼
⑤ 释放
   NOC_END_FLIT 发出后:
   - releaseOpticalPathForPacket(pktId)
   - 清空 edgeOccupancy 条目
   - SOA 电能耗累计：soaCount × pumpPower × duration
   - 从 ThermalModel 中减去 SOA/动态调谐功率
   - circuitReadyByDst 清零
```

### 6.3 关键数据结构

```
opticalEdgeOccupancy:
  map<edgeKey, vector<vector<int>>>
  // 每条无向边 → [numSpatialChannels][maxWavelengths] 矩阵
  // 非零值 = 占用该 (spatial, wavelength) 的 pktId

opticalPacketAllocations:
  map<pktId, OpticalPacketAllocation>
  // 每条活跃光路的完整信息（含 setupTime 用于 SOA 能耗计算）
```

## 七、功耗计算

### 7.1 PE 功耗（TaskPE.cc）

#### 静态功耗（泄漏）

```
leakageFactor = exp((T_pe - 318.15K) / 15.0)
idlePower    = powerIdle × leakageFactor     // 0.5W 基准 × 温度因子
computePower = (powerCompute - powerIdle)    // 1.5W 动态开关
             + powerIdle × leakageFactor     // + 计算期间泄漏
```

| 模式 | 功率组成 | 物理含义 |
|------|---------|---------|
| 空闲（idle） | `0.5W × leakageFactor` | 时钟关闭，仅泄漏电流 |
| 计算（compute） | `1.5W + 0.5W × leakageFactor` | 动态开关 + 泄漏基底 |

#### 动态功耗 — 电层收发

```
每窗口累计:
  N_electrical_send × 0.1 nJ   ← 电层发送（含 SETUP_REQ/ACK）
  N_electrical_recv × 0.05 nJ  ← 电层接收（含 Credit 返回）
```

#### 动态功耗 — 光层收发

```
每窗口累计:
  N_opt_send × 2 pJ   ← 调制器驱动（电→光转换）
  N_opt_recv × 1 pJ   ← 光电探测器+TIA（光→电转换）
```

### 7.2 Router 功耗（InPortSync.cc）

| 操作 | 能耗 | 物理含义 |
|------|:---:|------|
| Buffer Write | 1 pJ | SRAM 写 |
| Buffer Read | 1 pJ | SRAM 读 |
| Crossbar | 0.5 pJ | 纵横式交换开关 |
| 静态泄漏 | 1 mW × leakageFactor | 每端口基准 |

### 7.3 光器件功耗

| 项目 | 状态/条件 | 说明 |
|------|:---:|------|
| 微环静态热调谐 | **ON** | 160 环/路由器 × 2mW/环 = **320 mW/路由器**，16 路由器共 **5.12W** |
| SOA 逐跳放大 | **ON** | 每路由器输出端口后 SOA×80mW，13 dB 增益，按电路持续时间累计能耗 |
| MRR 动态热调谐 | OFF | `opticalEnableThermalEffects=false`，关闭温度漂移补偿 |
| 激光器电功率 | 未实现 | 仅光域 launchPower，无 WPE 模型 |

### 7.4 窗口汇总

```
windowDynamicEnergyJ = 电层收发 + 光层收发
windowStaticEnergyJ  = 静态泄漏功率 × 100ns
windowEnergyJ        = windowStaticEnergyJ + windowDynamicEnergyJ
windowAvgPower       = windowEnergyJ / 100ns

→ submitPEPower / submitRouterPower → ThermalModel 作为热源
```

## 八、热仿真（RC 热模型）

### 8.1 模型结构（ThermalTrace.cc）

**两层二维 RC 热网络**，PE 层和 Router 层各 `rows×cols` 个节点。每个节点：

```
dT_pe[i]/dt × Cpe =
    pePower[i]                                    ← 热源
  - (T_pe[i] - Tambient) / RconvPE                 ← 垂直对流
  - (T_pe[i] - T_router[i]) / Rpe2router           ← 垂直到本地 Router
  - Σ(T_pe[i] - T_pe[neighbor]) / RlateralPE       ← 横向传导

dT_router[i]/dt × Crouter =
    routerPower[i] + routerOpticalPower[i]          ← 电功率 + 光器件功率
  - (T_router[i] - Tambient) / RconvRouter
  - (T_router[i] - T_pe[i]) / Rpe2router
  - Σ(T_router[i] - T_router[neighbor]) / RlateralRouter
```

> `routerOpticalPower[i]` 包含微环静态热调谐功率（320mW/路由器，常驻）+ SOA 泵浦功率（建链时 add，拆链时 remove）。

### 8.2 求解方法

显式 Euler 法，每个 `energyWindow` (100ns) 推进一次：
```
T_new = T_old + (heatIn / C) × dt
```

### 8.3 温度反馈路径

```
温度 → DVFS 节流:  computeTime ×= (1 + 0.05 × (T-320))  当 T > 47°C
温度 → 泄漏功耗:    currentPower ×= exp((T-318.15)/15)
```

## 九、光损耗计算

### 9.1 简单线性模型（后备）

```
totalLoss_dB = 调制器损耗(2dB)
             + hopCount × (hopInsertionLoss(0.5dB) + hopCrosstalkLoss(0.1dB))
             + 解调器损耗(2dB)

receivedPower_dBm = launchPower_dBm(0) - totalLoss_dB
meetsSensitivity = receivedPower_dBm >= receiverSensitivity_dBm(-18)
signalMargin_dB = receivedPower_dBm - receiverSensitivity_dBm
```

### 9.2 设备级精细模型

`OpticalDeviceModel::computeDeviceLevelBudget()` 为每条光路构建完整物理设备链：

```
激光器 → 波导段 → 调制器微环链(环通过×N + 环下载)
  → 路由器内部(端口转向: 环通过×M + 环下载 + 波导弯曲)
  → 跨路由器波导段 → SOA
  → ... (重复 XY 维序路由每一跳)
  → 解调器微环链(环通过×K + 环下载) → 光电探测器
```

每段累加损耗，按设备类型查表（`OpticalDeviceModel.cc:260-379`），含温度修正（`opticalEnableThermalEffects=true` 时启用）。

### 9.3 SNR 与 BER 计算

```
rxPower_mW = 10^(rxPower_dBm/10)
totalNoise_mW = 热噪声 + ASE噪声 + 串扰噪声
SNR_linear = rxPower_mW / totalNoise_mW

PAM4: BER = 0.75 × erfc(√(SNR_linear / 10))
OOK:  BER = 0.5  × erfc(√(SNR_linear / 2))
```

> 预算不阻止建链。即使 BER 超标，光路仍建立。预算数据仅用于统计记录和可选的重路由触发。

## 十、光旁路 vs 纯电对比

### 10.1 小数据任务图（MPEG4，160B/flit 级）

光旁路和纯电仿真时间几乎相同（~180µs），因为任务图是 **compute-bound**——计算时间占总时间 99%+，数据通信占比 <1%。且短包（4-32 flit）在短距离（1-3 hop）场景下，光路握手 SETUP_REQ/ACK 开销（~20-30ns）可能超过电路由器的流水线延迟（~10-15ns）。

### 10.2 大数据长距离任务图（32KB，6 hops）

自建 `tasks_optic_advantage.csv` 测试（PE0→PE15 和 PE3→PE12，各 2048 flit × 6 hops）：

| 指标 | 光旁路 (ONoC_MPEG4) | 纯电 (General) |
|------|:---:|:---:|
| 全部任务完成时刻 | **27.27 µs** | 43.34 µs |
| 光 flit 数 | 4160 | 0 |

**光旁路快 37%**。单条 2048-flit 6-hop 传输：光路 ~540ns（握手 24ns + 2048×0.25ns），电路由器 ~2054ns——光路快 3.8×。大数据长路径摊平了握手开销。

## 十四、Python 仿真器 (mapping/)

### 14.1 概述

为支持离线的任务重映射（遗传算法/AI 算法），将 OMNeT++ 的核心仿真逻辑移植为 Python 模块。Python 仿真器产生与 OMNeT++ 一致的结果（完成时间偏差 <0.2%，温度偏差 <0.3K），但运行速度更快且易于嵌入优化循环。

### 14.2 模块清单

| 文件 | 功能 |
|------|------|
| `mapping/task_graph.py` | CSV 任务图解析，DAG 依赖，拓扑排序 |
| `mapping/noc_simulator.py` | 事件驱动光电混合 NoC 仿真器（核心） |
| `mapping/thermal_simulator.py` | 基于调度表的 RC 热仿真 + DVFS 闭环 |
| `mapping/cost_model.py` | 温度感知任务映射代价函数 |
| `mapping/optical_budget.py` | 器件级光功率预算计算 |

| `mapping/csv_writer.py` | 输出优化后的静态 CSV |
