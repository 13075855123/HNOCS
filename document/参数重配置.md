# 参数重配置

这里的判断标准不是“当前默认值能不能跑”，也不是照搬其他表格的建议值，而是按当前项目实现和主流成熟工艺的现实量级来定，避免把电层 baseline 设得过于先进，从而保留和光层对比的区分度。

## GPT

| 参数 | 当前值 | 建议值 | 说明 |
|:-:|:--:|:--:|:--|
| `**.statStartTime` | `1us` | `0ns` | 仿真没有预热阶段，直接从 0ns 统计最贴近真实 trace，也不会漏掉短任务。 |
| `**.Tthrottle` | `320.0K` | `333.15K` | 采用约 60°C 的保守节流阈值，不按更激进的先进工艺放宽热容限，便于保留和光层的对比差异。 |
| `**.throttleBeta` | `0.05` | `0.1` | 线性节流取 10%/°C，能让热降频对电层的影响可见，但仍是常见的简化模型量级。 |
| `**.RlateralChiplet` | `15` | `5 K/W` | 横向热耦合按项目默认的成熟值设置，避免把芯片间导热假设得过弱或过强。 |
| `**.RlateralRouter` | `15` | `5 K/W` | 同上，router 间横向热耦合也保持成熟工艺下的默认量级。 |
| `**.Rchiplet2router` | `3` | `2 K/W` | chiplet 到本地 router 的垂直热路径应强于横向路径，2 K/W 更符合项目热模型。 |
| `**.Crouter` | `2e-7` | `1e-7 J/K` | router 热容按较小面积设置，符合当前 mesh 结构的现实量级。 |
| `**.givenTclk` | `false` | `false` | 保持自动推导时钟，不额外把电层设成更有利的手工时钟配置。 |
| `**.tClk` | `1ns` | `8ns` | 若将来显式启用时钟，8ns 与 16B@16Gbps 的序列化时间匹配；当前 `false` 时该值不参与计算。 |
| `**.chiplet[*].computeDensity` | `0` | `0` | 保留 CSV 里的 computeTime，避免用合成密度值压缩或拉长真实计算负载。 |
| `**.chiplet[*].powerIdle` | `0.5W` | `0.3W` | 按成熟工艺下较保守的静态/待机功耗取值，不采用更激进的低功耗节点。 |
| `**.chiplet[*].powerSendPerFlit` | `1e-10J` | `3e-10J` | 采用更保守的电互连能耗，约 300 pJ/flit，符合成熟工艺下短距电链路的现实压力。 |
| `**.chiplet[*].powerRecvPerFlit` | `5e-11J` | `1.5e-10J` | 接收端仍按成熟工艺下的现实量级给出，避免把通信能耗估得过低。 |
| `**.chiplet[*].powerCompute` | `2.0W` | `3.0W` | 中等规模 chiplet 的峰值功耗取保守值，方便和光层低热负载形成对比。 |
| 链路 `delay` | `0 us` | `0 us` | 片上传播延迟是皮秒级，相比 8ns 序列化时间可忽略，保留 0us 更贴近当前实现。 |
| GB `initialCredits` | `4` | `8` | 8 个 credit 能避免注入端过早停顿，同时不把源侧窗口设得过大。 |
| GB 注入时钟 `tClk_s` | `2 ns` | `8ns` | 8ns 与链路带宽对应；2ns 只是更频繁轮询，8ns 更像真实节拍。 |

## DeepSeek

| 参数 | 当前值 | 建议值 | 说明 |
|:-:|:--:|:--:|:--|
| `**.statStartTime` | `1us` | `0ns` | 电 NoC 仿真从 t=0 即可进入稳态，0ns 保留首个能量窗和短任务的完整统计。 |
| `**.Tthrottle` | `320.0K` | `320.0K`（47°C） | 保持低节流阈值，凸显电层高功耗必然触发热节流；光层低功耗即使同阈值也不会频繁节流，对比鲜明。 |
| `**.throttleBeta` | `0.05` | `0.1`（10%/°C） | 10%/°C 让 DVFS 降频可见，量化电层因热节流产生的性能损失。 |
| `**.RlateralChiplet` | `15` | `15 K/W` | 弱横向热耦合 → 局部热点集中 → 电层更容易过热；光层低功耗即使在弱热耦合下也不会形成热点。 |
| `**.RlateralRouter` | `15` | `15 K/W` | 同上，router 间横向热隔离也保持保守假设。 |
| `**.Rchiplet2router` | `3` | `3 K/W` | 偏大的垂直热阻 → chiplet 热量难散 → 积热更严重；光层无此痛点。 |
| `**.Crouter` | `2e-7` | `1e-7 J/K` | router 小热容 → 温升快 → 热节流更敏感，反映电层的热惯性痛点。 |
| `**.givenTclk` | `false` | `false` | 由链路带宽和 flit 大小自动推导时钟。 |
| `**.tClk` | `1ns` | — | givenTclk=false 时不生效。 |
| `**.chiplet[*].computeDensity` | `0` | `0` | CSV trace 包含真实 computeTime，不 override 以保持任务负载真实性。 |
| `**.chiplet[*].powerIdle` | `0.5W` | `0.5W` | 保持较高的空闲功耗，增加电层总发热量；光层 idle 功耗可显著更低。 |
| `**.chiplet[*].powerSendPerFlit` | `1e-10J` | `3e-10J`（300 pJ） | 成熟工艺电 SerDes 的保守功耗，光层可轻松低一个数量级以上。 |
| `**.chiplet[*].powerRecvPerFlit` | `5e-11J` | `1.5e-10J`（150 pJ） | 接收端按 send/recv ≈ 2:1 的保守比例设定。 |
| `**.chiplet[*].powerCompute` | `2.0W` | `3.0W` | 偏高的 chiplet 计算功耗 → 更多发热 → 热节流更显著；光层无热负担。 |
| 链路 `delay` | `0 us` | `0 us` | 片上传播延迟可忽略。 |
| GB `initialCredits` | `4` | `4` | 保持小 credit 池，凸显 wormhole 流控下电层的注入瓶颈；光层可有更灵活流控。 |
| GB 注入时钟 `tClk_s` | `2 ns` | `2 ns` | 不调整注入节拍，保留当前 credit 不足导致的注入等待特征。 |

## MiMo

| 参数 | 当前值 | 建议值 | 说明 |
|:-:|:--:|:--:|:--|
| `**.statStartTime` | `1us` | `1us` | 跳过仿真启动瞬态即可，对统计结果影响不大。 |
| `**.Tthrottle` | `320.0 K`（47°C） | `320.0 K`（47°C） | 距 Tambient（45°C）仅 15°C，几乎所有负载都触发节流——这正是保守电层 baseline 的特征。光层功耗低，同阈值下温度更低、节流更少，优势一目了然。 |
| `**.throttleBeta` | `0.05`（5%/°C） | `0.1`（10%/°C） | 0.05 减速太轻，超温后效果不明显；0.1 让 DVFS 节流可见，便于量化电层性能损失。 |
| `**.RlateralChiplet` | `15 K/W` | `15 K/W` | 保守假设：横向热耦合极弱，热点难以扩散，chiplet 层容易局部过热。光层功耗低，即使热耦合弱也不会过热，对比更鲜明。 |
| `**.RlateralRouter` | `15 K/W` | `15 K/W` | 同上，router 间横向热耦合也弱，热隔离假设一致。 |
| `**.Rchiplet2router` | `3 K/W` | `3 K/W` | 垂直热阻大于横向，chiplet 热量传到 router 受阻，保守假设让 chiplet 层更容易积热。 |
| `**.Crouter` | `2e-7 J/K` | `1e-7 J/K` | router 面积远小于 chiplet，热容应成比例缩小；小热容→温度响应快→热节流更敏感。 |
| `**.givenTclk` | `false` | `false` | 保持自动推导，由链路带宽和 flit 大小决定时钟周期。 |
| `**.tClk` | `1ns` | — | givenTclk=false 时不生效。 |
| `**.chiplet[*].computeDensity` | `0` | `0` | 用 CSV trace 驱动计算时间，贴近真实应用行为。 |
| `**.chiplet[*].powerIdle` | `0.5W` | `0.1W` | 0.5 W 对单个 chiplet 静态功耗偏高，0.1 W 更接近实际泄漏水平。 |
| `**.chiplet[*].powerSendPerFlit` | `1e-10J` | `1e-10J` | 100 pJ/flit，保守的电层 SerDes 功耗，光层对应值可低一个数量级。 |
| `**.chiplet[*].powerRecvPerFlit` | `5e-11J` | `5e-11J` | 50 pJ/flit，接收端功耗低于发送端，典型电层值。 |
| `**.chiplet[*].powerCompute` | `2.0W` | `2.0W` | 中等规模计算 chiplet 的合理峰值功耗。 |
| 链路 `delay` | `0 us` | `0 us` | 片上互连距离 <2mm，传播延迟可忽略。 |
| GB `initialCredits` | `4` | `4` | 保守的流控设置，credit 少→注入受限→突出电层带宽瓶颈。 |
| GB 注入时钟 `tClk_s` | `2 ns` | `2 ns` | 当前硬编码值，保持不变。 |
