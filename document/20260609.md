## 二、逐基准详细分析

### 2.1 GEMM (CCR=8, Fork-join 归约树, 11 任务)

**全维度正向——最优结果。**

```
ΔT_max:   -1.2°C     (54.9→53.7)
Δσ_T:     -22.8%      (2.55→1.97K)
ΔN_hot:   -6          (6→0)
ΔMakespan: -3.2%     (119.6→115.8μs)
Δη_dvfs:  -100%       (1.77%→0.00%)
ΔE_SOA:   -67.1%      (1.288→0.423μJ)
ΔE_tune:  -71.3%      (111.0→31.9nJ)
ΔE_total: -3.5%       (1.581→1.526mJ)
ΔComm:    -59.8%      (104,448→41,984)
Speedup:   1.033×
```

**成因**: GEMM 的通信密集型 Fork-join 结构对 GA 最友好。GA 将通信任务聚集到邻近 PE（Comm -60%），直接缩短光路径长度，减少 SOA 级数和 MRR 激活量。同时，热负载分布更均匀（σ_T -23%），消除全部 6 个过热 PE。这是唯一实现全指标同步改善的基准。

**收敛**: fitness 3.37→2.32 (-31.2%)，主要跳跃在第 3、8、29 代，中间存在 10-28 代的长期平台期，表明 GA 陷于局部最优后通过突变跳出。

---

### 2.2 VOPD (CCR=0.3, 长流水线, 13 任务)

**性能大幅跃升——超出预期的惊喜。**

```
ΔT_max:   -0.1°C     (52.2→52.1)
Δσ_T:     +15.7%      (1.15→1.33K)  ← 热均匀性反而恶化
ΔN_hot:   0→0
ΔMakespan: -37.8%    (87.4→54.4μs)   ← 论文核心亮点
Δη_dvfs:  0.00→0.00%
ΔE_SOA:   +2.2%       (1.574→1.608μJ)
ΔE_tune:  +16.5%      (106.3→123.8nJ)
ΔE_total: -23.8%      (0.753→0.574mJ)
ΔComm:    -59.5%      (1,396K→566K)
Speedup:   1.607×     ← 论文最强加速比
```

**成因**: VOPD 的长流水线结构包含大量级间通信（基线 Comm=1396K，为 5 基准中第二高）。GA 将通信距离削减 60%，大幅缩短光路建立延迟和传输时间，makespan 从 87.4μs 降至 54.4μs（-38%）。但任务集中到更少 PE 导致 σ_T 上升 16%——活跃/空闲 PE 温差拉大。然而 T_max 未恶化（仅降 0.1°C），因为 makespan 缩短使总热注入时间大幅减少。

**关键洞察**: σ_T 上升 + Makespan 暴降 = Pareto 最优的"牺牲热均匀性换性能"策略。这是 GA 根据代价函数权重自主选择的方向——$w_D=2.0$ 和 $w_H=1.0$ 使算法倾向于降低通信代价，即使以 σ_T 微升为代价。与之前 Python-only GA 中 VOPD 表现最差形成鲜明对比，OMNeT++ 在环评估成功捕捉到了光层效应。

**收敛**: fitness 3.96→2.66 (-32.9%)，前 5 代快速下降后平缓改善。

---

### 2.3 MPEG4 (CCR≈1, Fork-join + 分支, 12 任务)

**温和的热改善，以性能为代价。**

```
ΔT_max:   -1.5°C     (54.4→53.0)    ← 温降幅度最大
Δσ_T:     -14.3%      (1.54→1.32K)
ΔN_hot:   -2          (2→0)
ΔMakespan: +11.0%    (121.7→135.1μs) ← 性能退化
Δη_dvfs:  -100%       (0.06%→0.00%)
ΔE_SOA:   -23.2%      (1.322→1.015μJ)
ΔE_tune:  -53.4%      (95.8→44.6nJ)
ΔE_total: +6.2%       (1.144→1.215mJ)
ΔComm:    -52.4%      (420K→200K)
Speedup:   0.901×
```

**成因**: MPEG4 的均衡 CCR 使 GA 在热散布与通信局部性之间面临 trade-off。通信跳数减半（-52%），SOA 能耗降 23%，调谐能耗降 53%。但任务集中化导致光路竞争加剧——在相同边上同时建立多条光电路引发波长争用，增加了电路建立等待时间。结果 makespan 反升 11%，PE 总能耗从 1.142→1.213mJ（+6.2%）。

**关键洞察**: 通信局部化并非总能转化为性能收益。在 CCR≈1 的平衡区，波长槽竞争成为瓶颈——16 槽/边在集中通信模式下不够用。这揭示了代价函数的一个盲区：$f_{\text{comm}}$ 只惩罚通信距离，不惩罚通信密度（每边并发电路数）。

**收敛**: fitness 4.26→2.76 (-35.1%)。

---

### 2.4 HNN (CCR=3, 4 级流水线, 33 任务)

**热大胜，性能大损——代价函数权重失衡的典型案例。**

```
ΔT_max:   -1.1°C     (55.7→54.6)
Δσ_T:     -33.6%      (3.05→2.03K)   ← 热均匀性改善最大
ΔN_hot:   -13         (16→3)          ← 过热 PE 从全部 16 个降至 3 个
ΔMakespan: +77.3%    (204.1→361.8μs) ← 严重退化
Δη_dvfs:  -99.7%      (11.0%→0.03%)  ← DVFS 几乎清零
ΔE_SOA:   -0.8%       (3.750→3.719μJ)
ΔE_tune:  -51.1%      (474.9→232.4nJ)
ΔE_total: +9.3%       (4.681→5.114mJ)
ΔComm:    -51.9%      (2,195K→1,057K)
Speedup:   0.564×
```

**成因**: HNN 拥有 33 个任务的大搜索空间（$16^{33}$），4 级流水线中存在大量可并行的 Stage 3 任务（16 PE 可同时执行）。基线映射充分利用了并行度，但代价是 16 个 PE 全部过热（N_hot=16），DVFS 节流比高达 11%。

GA 以 $w_T=1.0$ 驱动，优先压降温度。策略是将大量任务串行化到少数冷却更快的 PE 上，减少同时活跃的 PE 数量。效果显著：N_hot 从 16→3，σ_T 从 3.05→2.03K，DVFS 几乎归零。但代价是破坏了流水线并行度——makespan 从 204μs 飙升至 362μs（+77%），PE 总能耗 +9.3%。

**关键洞察**: 这是代价函数缺少 makespan 直接惩罚项的严重后果。$w_T$ 相对 makespan 隐式权重过高，导致 GA 为了降温不惜牺牲 DAG 并行度。论文中这恰好证明了"需要在代价函数中显式编码 makespan"——单靠热指标驱动不足以保证全局最优。

**收敛**: fitness 19.54→7.13 (-63.5%)，降幅最大，因为基线复合代价极高（热+通信双高）。大搜索空间意味着 30 代仍远未收敛。

### 2.5 Optic (CCR=0.06, 星型全并行, 16 任务)

**基本不变——预期之内。**

```
ΔT_max:   ±0.0°C     (48.8→48.8)
Δσ_T:     -2.7%       (1.01→0.98K)
ΔN_hot:   0→0
ΔMakespan: +0.2%     (9.23→9.25μs)
Δη_dvfs:  0.00→0.00%
ΔE_SOA:   -9.9%       (12.748→11.495μJ)
ΔE_tune:  +0.5%       (42.1→42.3nJ)
ΔE_total: -1.9%       (0.106→0.104mJ)
ΔComm:    0→0
Speedup:   0.998×
收敛:      19 代早停
```

**成因**: Optic 的 16 个 task 完全独立——零通信边，仅向 GlobalBuffer 写回数据。通信代价恒为零，负载在 16 PE 间均匀分配已是近似最优。GA 唯一的操作空间是微调负载均衡，但 PE 数量等于 task 数量（16=16），最优解即每个 PE 一个 task。19 代即收敛（全基准唯一早停）。

复合代价从 0.421→0.484（+14%），但实际物理指标基本不变——代价函数的微小波动来自仿真噪声，而非映射质量的真实差异。

**角色**: Optic 作为"无可优化空间的对照组"，确立优化上界。与其他 4 个基准的对比验证了 GA 在存在优化空间时的有效性。

## 三、σ_T 的三重角色——论文核心叙事

σ_T（温度标准差）并非单调改善，而是根据基准特性呈现三种模式：

| 基准 | Δσ_T | ΔMakespan | 模式 | 解读 |
|------|:--:|:--:|------|------|
| **GEMM** | -23% | -3% | **热性能双赢** | 通信局部化 + 热均匀化协同 |
| **MPEG4** | -14% | +11% | **热改善换性能** | 光路争用抵消通信收益 |
| **HNN** | -34% | +77% | **过度冷却** | 代价函数权重失衡，牺牲并行度 |
| **VOPD** | +16% | -38% | **性能换热均匀性** | Pareto 最优：集中=更快但更不均 |
| **Optic** | -3% | ±0% | **无优化空间** | 独立任务，baseline 即最优 |

**结论**: σ_T 不是越低越好。VOPD 的 σ_T 上升恰是合理策略——GA 自主选择用 σ_T 换 makespan。论文可将其建模为 σ_T vs Makespan 的 Pareto 前沿，论证任务映射是一个多目标优化问题。

### 4.2 avg_fitness 问题

所有基准的历史记录中 `avg_fitness` 在前中期均为 `Infinity`。原因：部分个体产生病态映射（光层事件爆炸），OMNeT++ 超时返回 inf。随着种群进化，有效个体比例逐渐上升。GEMM 在第 28 代才首次出现有限 avg_fitness（2.55）。

**改进方向**: 提高超时阈值（60→120s）或加入映射合法性预筛选（如检测 DAG 关键路径上的 PE 集中度）。

### 4.3 早停与收敛

仅 Optic 触发早停（19 代，patience=10）。其余 4 基准均跑满 30 代，但 GEMM 存在 10-28 代（18 代）的长期平台期——fitness 在 2.425→2.342 间缓慢改善，严格说来应触发早停。但由于 inf 个体的存在，代间最优个体并非连续同一条，导致早停计数器被重置。

## 五、光层能耗分解

### 5.1 光层三组分变化

| 基准 | ΔE_SOA | ΔE_tune | ΔE_laser | 主导效应 |
|------|:--:|:--:|:--:|------|
| GEMM | **-67%** | **-71%** | -3% | 通信距离缩短 → 光路径变短 → SOA + MRR 双降 |
| MPEG4 | **-23%** | **-53%** | +11% | 通信距离缩短 → 调谐降，但电路持续时间延长 → laser 升 |
| VOPD | +2% | +17% | **-37%** | Makespan 缩短 → laser CW 时间减少 → 主导节能 |
| HNN | -1% | **-51%** | +77% | Makespan 翻倍 → laser CW 时间翻倍 → 吃掉调谐节省 |
| Optic | **-10%** | +1% | -1% | 负载微调使部分电路更短 |

### 5.2 能效洞察

- **SOA 能耗与通信跳数正相关但不线性**：VOPD 通信跳数 -59% 但 SOA 能耗 +2%（光路径虽短但波长争用导致电路持续时间更长）。
- **调谐能耗最敏感**：GEMM -71%，MPEG4 -53%，HNN -51%。通信局部化直接减少活跃 MRR 数量，是 GA 优化最有效的能耗杠杆。
- **Laser 能耗反映 makespan**：VOPD 的 laser -37%（makespan 缩短 38%），HNN 的 laser +77%（makespan 延长 77%）。Laser CW 常亮，能耗与仿真时间成正比。

## 六、方法对比：OMNeT++ 在环 vs Python 优化器

本实验使用 OMNeT++ 全系统仿真作为 GA 适应度评估器，与先前 Python 热仿真器评估（B2_algorithm.md）的关键差异：

| 维度 | Python 优化器 | OMNeT++ 在环（本实验） |
|------|:---:|:---:|
| 光层建模 | 无（仅通信跳数） | 完整 WDM + SOA + MRR 调谐 |
| 波长争用 | 未建模 | 逐边逐槽实时分配 |
| 热-光耦合 | 无 | MRR 调谐功率反馈到热模型 |
| DVFS 精度 | 简化 | 每 100ns 周期性重评估 |
| VOPD 表现 | **最差** (makespan +1.4%) | **最佳** (makespan -38%) |
| GEMM 表现 | 全指标优于 BL | 全指标优于 BL |
| HNN 表现 | 仿真崩溃 | 完成但 makespan +77% |

**核心教训**: VOPD 的结果反转最具说服力——Python 优化器下 VOPD 表现最差（光层竞争未建模导致负优化），但 OMNeT++ 在环评估下 VOPD 表现最佳。光层竞争和热-光耦合的完整效应只能在全系统仿真中被准确捕捉。

## 七、代价函数改进建议

基于 5 基准实验结果，提出以下改进方向：

1. **加入 makespan 直接惩罚项**：$w_M \cdot t_{\text{makespan}} / t_{\text{nominal}}$。HNN 的结果表明缺少此项会导致 GA 牺牲并行度换取热指标。

2. **加入通信密度惩罚**：$w_C \cdot \max_{\text{edge}} (\text{concurrent\_circuits})$。MPEG4 的问题源于通信集中在少数边上引发波长争用。

3. **自适应权重**：对于 CCR>1 的基准提高 $w_M$（防 makespan 退化），对于 CCR<0.3 的基准提高 $w_H$（充分利用通信优化空间）。

4. **代理模型预筛选**：使用快速分析模型过滤明显不可行的映射（如 DAG 关键路径上 >50% task 集中在同一 PE），减少 OMNeT++ 超时次数。

## 八、论文定位建议

### ACP 2026 适配要点

ACP 是光子学会议，论文叙事应围绕：

1. **热光效应**：MRR 热敏感性是光 NoC 的核心物理挑战（而非纯算法问题）
2. **光层能耗**：SOA 泵浦 + MRR 调谐占光通信能耗 60-80%
3. **器件-架构协同**：任务映射是架桥梁——连接"器件级热调谐"和"系统级性能能耗"
4. **量化光层收益**：不是简单的"温度降了"，而是"温度降了→MRR 调谐功率降→SOA 跳数降→光层能耗降"

### 叙事主线

```
ONoC 面临 MRR 热敏感性挑战
  → 现有方案：器件级（无热化）+ 电路级（选择性调谐）
  → 本文填补空白：架构级（任务映射）
  → 方法：GA 搜索 + OMNeT++ 全系统评估
  → 发现：
      1. GEMM: 热/性能/能耗三赢 (T_max -1.2°C, E_SOA -67%)
      2. VOPD: 性能大幅跃升 (Makespan -38%)
      3. HNN: 揭示代价函数需多目标平衡 (N_hot -81% 但 Makespan +77%)
      4. σ_T vs Makespan 构成 Pareto 前沿
  → 结论：任务映射是 ONoC 热优化的有效设计时手段，零硬件成本
```
