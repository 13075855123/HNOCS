# [ONoCGeneral] 当前实现完整说明

> 生成日期: 2026-05-26
> 对应配置: `examples/task_driven/omnetpp.ini` → `[ONoCGeneral]`
> 继承基准: `[General]`（纯电基线，TaskMesh + XYOPCalc）

---

## 一、总体描述

**完整的 task-driven 光电混合 NoC 仿真**：电层控制面握手 → 光层数据直传 → 可重构波长分配 → 设备级光链路预算 → RC 热模型 → DVFS 节流。

```
控制面（电）:  setup_req → 电 router → setup_ack
数据面（光）:  data flit → sendDirect → 光波导一跳直达
```

## 三、波长分配机制

### 分配触发时机

波长分配在 `LogicalTopologyManager::tryAllocateOpticalPathForPacket()` 中完成（`src/onoc/control/LogicalTopologyManager.cc:1481`），由源路由器上的 **ReconfigurableOPCalc** 在第一个数据 flit 到达时触发。

### 完整流程

```
源 PE 完成计算 → 需要发数据给下游
        │
        ▼
① 电层握手 (setup handshake)
   - TaskPE.cc:1010 调用 tryReserveSetupPath(dst)
   - LogicalTopologyManager 在 edgeOccupancy 中预留波长+空间通道
   - 通过电路由器发 SETUP_REQ（2-flit 控制包，taskId=-1）
   - 目的 PE 收到后发 SETUP_ACK 回应
   - 源 PE 收到 ACK，标记 circuitReadyByDst[srcIdx] = 1
   - 超时重试：setupRetryDelay=50ns, setupPendingTimeout=200ns
        │
        ▼
② 数据 flit 触发波长分配
   第一个 NOC_START_FLIT 到达源路由器时 (ReconfigurableOPCalc.cc:312):
   - 若 srcId == routerId 且波长尚未分配
   - → topologyManager->tryAllocateOpticalPathForPacket(src, dst, pktId)
        │
        ▼
③ 核心分配算法 (LogicalTopologyManager.cc:1523-1565)
   a. buildXYPathEdges() — 确定源到目的地的 XY 维序路由边列表
   b. 确定所需波长数（默认 2 个：opticalRequiredWavelengths）
   c. 遍历空间通道 (0 → numOpticalSpatialChannels-1):
      - isWavelengthFreeOnPath(): 检查每个波长是否在所有边上空闲
      - 收集所有空闲波长索引
      - 策略 "lowest": 直接取最小的 required 个空闲波长
      - 策略 "thermal": 评测候选组合的光预算，选调谐功率最小的（当前未启用）
      - 若空闲波长不足 → 尝试下一个空间通道
   d. 占用波长: edgeOccupancy[spatial][wlIdx] = pktId（所有边）
   e. 存储分配: opticalPacketAllocations[pktId] = {src, dst, spatial, wls, edges}
   f. 预计算设备级光链路预算并缓存
   g. 若所有空间通道都不够 → insufficientResources = true → 丢包
        │
        ▼
④ 光层数据直传
   TaskPE.cc:659 sendOpticalFlitFromQ()
   - 从 opticalDataQ 取 flit
   - sendDirect(flit, propDelay, txDuration, targetMod->opticalIn)
   - 数据 flit 通过 OMNeT++ sendDirect 在光链路上端到端直传
   - 完全绕过电路由器的 store-and-forward
        │
        ▼
⑤ 释放
   NOC_END_FLIT 发出后:
   - releaseOpticalPathForPacket(pktId)
   - 清空所有路径边上的 edgeOccupancy 条目
   - 从 opticalPacketAllocations 中移除
   - 若使用了 SOA/调谐功率，从 ThermalModel 中减去
   - circuitReadyByDst 清零
```

### 关键数据结构

```
opticalEdgeOccupancy:
  map<edgeKey, vector<vector<int>>>
  // 每条无向边 → [numSpatialChannels][maxWavelengths] 矩阵
  // 非零值 = 占用该 (spatial, wavelength) 的 pktId
  // 零 = 空闲

opticalPacketAllocations:
  map<pktId, OpticalPacketAllocation>
  // 每条活跃光路的完整信息
```

### 当前策略

- **`"lowest"`**: 遍历空闲波长表，选索引最小的 N 个。快速、确定性。
- **无热感知**: `opticalEnableThermalEffects = false` → 不评估温度对 MRR 谐振的影响，不计算调谐功率。

## 四、功耗计算

功耗计算以 `energyWindow`（100ns）为粒度。每个窗口结束时，各模块统计本窗口的静态和动态能耗，提交给 ThermalModel 驱动热仿真。

### PE 功耗（TaskPE.cc）

PE 的功耗 = **静态泄漏功耗** + **动态开关功耗**。动态部分又分为电层收发和光层收发两条路径。

#### 1. 静态功耗（泄漏电流）

PE 即使不工作，晶体管也存在亚阈值泄漏电流。泄漏功耗随温度指数增长：

```
leakageFactor = exp((T_pe - 318.15K) / 15.0)
// 温度每升高约 10°C，泄漏功耗约翻倍

idlePower    = powerIdle × leakageFactor     // 空闲态泄漏: 0.5W 基准 × 温度因子
computePower = (powerCompute - powerIdle)    // 计算时的动态开关功耗（2.0W - 0.5W = 1.5W 净增量）
             + powerIdle × leakageFactor     // + 计算期间的泄漏（与空闲态相同）

windowStaticEnergyJ = 当前 power × dt 的积分（每 energyWindow 累加）
```

**各模式功率：**

| 模式 | 功率组成 | 物理含义 |
|------|---------|---------|
| 空闲（idle） | `0.5W × leakageFactor` | 时钟关闭，仅泄漏电流 |
| 计算（compute） | `1.5W + 0.5W × leakageFactor` | 动态开关功耗 1.5W + 泄漏基底 |

#### 2. 动态功耗 — 电层收发

PE 通过电路由器（`send()` + channel 连线）收发的每个 flit 消耗固定的开关能量。这些 flit 包括握手控制包（SETUP_REQ/ACK）、纯电模式下的数据 flit、以及 Credit 流控消息。

```
每窗口累计:
  N_electrical_send × powerSendPerFlit    = N × 0.1 nJ   ← 电层发送（含 SETUP_REQ/ACK）
  N_electrical_recv × powerRecvPerFlit    = N × 0.05 nJ  ← 电层接收（含 Credit 返回）
```

| 参数 | 值 | 物理含义 |
|------|-----|---------|
| `powerSendPerFlit` | 0.1 nJ/flit | PE→路由器链路的发送端驱动能耗，含端口驱动器和线电容充放电 |
| `powerRecvPerFlit` | 0.05 nJ/flit | 路由器→PE 链路的接收端采样能耗，含输入缓冲级 |

#### 3. 动态功耗 — 光层收发

光旁路模式下，数据 flit 走 `sendDirect()` 光路直传。光层能耗远低于电层（皮焦 vs 纳焦），因为光传输无需经过多跳路由器的 store-and-forward。

```
每窗口累计:
  N_opt_send × opticalModulatorEnergyPerFlit    = N × 2 pJ   ← 调制器驱动（电→光转换）
  N_opt_recv × opticalReceiverEnergyPerFlit     = N × 1 pJ   ← 光电探测器+TIA（光→电转换）
```

| 参数 | 值 | 物理含义 |
|------|-----|---------|
| `opticalModulatorEnergyPerFlit` | 2 pJ/flit | 微环调制器的驱动电路能耗（每 flit 加载到调制器上） |
| `opticalReceiverEnergyPerFlit` | 1 pJ/flit | 片端光电探测器 + 跨阻放大器（TIA）的信号恢复能耗 |

> 光层收发不包含激光器电功耗（当前未建模 WPE），也不包含光路传输途中的微环热调谐和 SOA 泵浦功耗（当前 `opticalEnableThermalEffects=false`，关闭了这些）。

#### 4. 窗口汇总与送入热模型

```
windowDynamicEnergyJ = 电层收发 + 光层收发（上述四项之和）
windowStaticEnergyJ  = 静态泄漏功率在 100ns 窗口内的积分
windowEnergyJ        = windowStaticEnergyJ + windowDynamicEnergyJ
windowAvgPower       = windowEnergyJ / 100ns

→ submitPEPower(peId, now, windowAvgPower) → ThermalModel 作为 PE 层热源
```

### Router 功耗（InPortSync.cc）

路由器功耗由每个端口（`InPortSync`）独立统计，再由 `port[0]` 汇总整个路由器的所有端口功耗，提交给 ThermalModel。

每个端口的功耗 = **静态泄漏** + **三种动态操作**的能耗。

#### 1. 静态功耗（泄漏）

```
windowStaticEnergyJ = pLeak × leakageFactor × energyWindow
                    = 1mW × exp((T_router - 318.15K) / 15.0) × 100ns
```

路由器端口的泄漏功耗基准为 1mW（`pLeak`），乘以与 PE 相同的温度相关泄漏因子。

#### 2. 动态功耗 — Buffer 写入

每当一个 flit 从上游链路到达并写入本端口的 VC 缓冲区（`InPortSync.cc:339,437`），累加一次 Buffer Write 能耗：

```
N_bufferWrite × eBufferWrite = N × 1 pJ
```

| 操作 | 触发时机 | 物理含义 |
|------|---------|---------|
| Buffer Write | flit 到达，写入对应 VC 的 flit 队列 | SRAM 写操作能耗 |

#### 3. 动态功耗 — Buffer 读出

每当一个 flit 从 VC 缓冲区读出，准备通过 Crossbar 发送或进行路由计算（`InPortSync.cc:459,472`），累加一次 Buffer Read 能耗：

```
N_bufferRead × eBufferRead = N × 1 pJ
```

| 操作 | 触发时机 | 物理含义 |
|------|---------|---------|
| Buffer Read | 从 VC 队列取出 flit，送 OPCalc/VCCalc/Crossbar | SRAM 读操作能耗 |

#### 4. 动态功耗 — Crossbar 穿越

当一个 flit 成功获得输出端口仲裁并通过 Crossbar 交换结构（`InPortSync.cc:290`），累加一次 Crossbar 能耗：

```
N_crossbar × eCrossbar = N × 0.5 pJ
```

| 操作 | 触发时机 | 物理含义 |
|------|---------|---------|
| Crossbar | flit 通过路由器的纵横式交换开关 | 横截点导线充放电 + 仲裁电路能耗 |

#### 5. 汇总

```
windowDynamicEnergyJ = bufferWrite + bufferRead + crossbar
windowStaticEnergyJ  = pLeak × leakageFactor × energyWindow
windowEnergyJ        = windowStaticEnergyJ + windowDynamicEnergyJ

→ port[0] 汇总所有端口 → submitRouterPower(routerId, now, avgPower) → ThermalModel
```

### 光器件功耗

因 `opticalEnableThermalEffects = false`，以下两项**均为 0**：

| 项目 | 条件 | 说明 |
|---|---|---|
| MRR 热调谐功率 | `opticalEnableThermalEffects=true` 时 | 补偿温度引起的谐振波长漂移所需的加热功率 |
| SOA 泵浦功率 | SOA 使能时 | 每 SOA 约 15 mW 电泵浦功率 |

### 当前未建模的功耗

- **激光器电功率**: 仅有光域 `launchPower_dBm`，无电→光转换效率（WPE）模型
- **光调制器/接收器驱动电路功耗**: 仅有每 flit 能量，无静态偏置功耗

## 五、热仿真（RC 热模型）

### 模型结构（ThermalTrace.cc:261 `updateTemperature`）

**两层二维 RC 热网络**，PE 层和 Router 层各 `rows×cols` 个节点。每个节点：

```
dT_pe[i]/dt × Cpe =
    pePower[i]                                    ← 热源
  - (T_pe[i] - Tambient) / RconvPE                 ← 垂直对流到环境
  - (T_pe[i] - T_router[i]) / Rpe2router           ← 垂直到本地 Router
  - Σ(T_pe[i] - T_pe[neighbor]) / RlateralPE       ← 横向传导到邻居 PE

dT_router[i]/dt × Crouter =
    routerPower[i] + routerOpticalPower[i]          ← 电功率 + 光器件功率
  - (T_router[i] - Tambient) / RconvRouter
  - (T_router[i] - T_pe[i]) / Rpe2router
  - Σ(T_router[i] - T_router[neighbor]) / RlateralRouter
```

### 求解方法

**显式 Euler 法**，每个 `energyWindow` (100ns) 推进一次：
```
T_new = T_old + (heatIn / C) × dt
```

### 触发机制（`tryFlush`）

```
每个 energyWindow 结束时:
  1. 各 PE 调用 submitPEPower(peId, t, avgPower)
  2. 各 Router 调用 submitRouterPower(routerId, t, avgPower)
  3. 当所有节点都提交了本窗口功率 → tryFlush() 触发
  4. routerPower[i] += routerOpticalPower[i]（合并光器件功率）
  5. updateTemperature(dt) → Euler 推进
  6. 写 HotSpot 格式热 trace 文件
  7. 为下一个窗口重置 ready 标志
```

### 温度反馈路径

```
温度 → DVFS 节流:  computeTime ×= (1 + 0.05 × (T-320))  当 T > 47°C
温度 → 泄漏功耗:    currentPower ×= exp((T-318.15)/15)
```

### 光学热效应状态

`opticalEnableThermalEffects = false` → 以下**全部关闭**：
- MRR 谐振波长温漂（thermo-optic coefficient）
- 温漂引起的额外插入损耗
- 补偿温漂所需的调谐功率
- SOA 增益温度退化
- 波导温度相关额外损耗

## 六、光损耗计算

### 简单线性模型（后备）

```
totalLoss_dB = 调制器损耗(2dB)
             + hopCount × (hopInsertionLoss(0.5dB) + hopCrosstalkLoss(0.1dB))
             + 解调器损耗(2dB)

receivedPower_dBm = launchPower_dBm(0) - totalLoss_dB
meetsSensitivity = receivedPower_dBm >= receiverSensitivity_dBm(-18)
signalMargin_dB = receivedPower_dBm - receiverSensitivity_dBm
```

### 设备级精细模型（实际使用）

`OpticalDeviceModel::computeDeviceLevelBudget()` (`src/onoc/common/OpticalDeviceModel.cc:387`) 为每条光路构建完整物理设备链：

```
激光器 → 波导段 → 调制器微环链(环通过×N + 环下载)
  → 路由器内部(端口转向: 环通过×M + 环下载 + 波导弯曲)
  → 跨路由器波导段 → SOA
  → ... (重复 XY 维序路由每一跳)
  → 解调器微环链(环通过×K + 环下载) → 光电探测器
```

每段累加：

| 损耗来源 | 建模方式 |
|---|---|
| 调制器/解调器 | 环通过损耗 0.05 dB/环 + 环下载 1.0 dB |
| 路由器内部 | 环通过次数依赖端口转向（波长相关公式），每跳 1 次下载 + 弯曲损耗 0.01 dB/次 |
| 波导传播 | 1.5 dB/cm × 段长 |
| SOA | 增益 13 dB（负损耗）+ ASE 噪声（NF=7 dB, B=30 GHz） |
| 相邻串扰 | -20 dB 泄漏到相邻波长通道 |
| 非相邻串扰 | -40 dB 泄漏到非相邻通道 |
| 解调器串扰 | λ_{i-1} 的通过端口泄漏到 λ_i 的下载端口 |

### SNR 与 BER 计算

```
rxPower_mW = 10^(rxPower_dBm/10)
totalNoise_mW = 热噪声(mW) + ASE噪声(mW) + 串扰噪声(mW)
SNR_linear = rxPower_mW / totalNoise_mW
SNR_dB = 10 × log10(SNR_linear)

PAM4: BER = 0.75 × erfc(√(SNR_linear / 10))
OOK:  BER = 0.5  × erfc(√(SNR_linear / 2))
```

### 链路预算的角色

**预算不阻止建链。** 即使 BER 超标或 receivedPower < sensitivity，光路仍会建立。预算数据仅用于：
- 统计记录（`opticalPathTotalLossDb`, `opticalPathReceivedPowerDbm`, `opticalPathMarginDb`）
- 可选的重路由触发（`enableBudgetBasedRerouting`，当前默认 false）
